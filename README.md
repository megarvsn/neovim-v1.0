# NeoVim IDE для веб-разработки (HTML/SCSS/JS + 1С-Битрикс + MySQL)

Конфигурация построена как IDE для фронтенда (html, scss, javascript, svg) и бэкенда на
1С-Битрикс с MySQL. Проекты с сервера монтируются по sshfs в `~/Projects/<имя>` — Neovim
работает с ними как с обычными папками: при первом открытии файлы скачиваются с сервера
автоматически (это делает sshfs), при сохранении — отправляются на сервер сразу.
Для работы с базой данных сервера используется vim-dadbod через SSH-туннель.

## Архитектура конфигурации

```
init.lua                  — точка входа
lua/
├── core/
│   ├── configs.lua       — базовые настройки Neovim (номера строк, клавиатура, undo)
│   ├── mappings.lua      — глобальные горячие клавиши
│   ├── cssjump.lua       — переход от html-класса/ID к его определению в стилях
│   ├── lazy.lua          — bootstrap и настройки менеджера плагинов lazy.nvim
│   └── sshfs.lua         — команды :SshfsMount/:SshfsUnmount/:SshfsList/:SshTunnel
└── plugins/              — по файлу на плагин (auto-импортируются lazy.nvim)
    ├── lsp.lua           — LSP-серверы и их настройки
    ├── mason.lua         — установка LSP-серверов и инструментов
    ├── treesitter.lua    — парсеры и подсветка
    ├── cmp.lua           — автодополнение
    ├── autotag.lua       — авто-пары html-тегов (закрытие и переименование пары)
    ├── conform.lua       — форматирование при сохранении
    ├── nvim-lint.lua     — линтеры (eslint для js/ts)
    ├── autopairs.lua     — авто-закрытие скобок и кавычек
    ├── indent.lua        — линии отступов (вложенность блоков)
    ├── dadbod.lua        — доступ к MySQL
    ├── matchup.lua       — подсветка парного тега/скобки и прыжок по %
    ├── rainbow.lua       — радужные цвета вложенных тегов/скобок
    ├── undo.lua          — локальная история версий (persistent undo)
    ├── fugitive.lua      — git для своих серверов и GitHub
    ├── gitsigns.lua      — git-знаки в строках
    ├── telescope.lua     — поиск/навигация
    ├── neo-tree.lua      — дерево файлов
    ├── bufferline.lua    — вкладки-буферы
    ├── lualine.lua       — статусная строка
    ├── dashboard.lua     — стартовый экран
    ├── kanagawa.lua      — цветовая тема (тёплая, wave)
    ├── which-key.lua     — справочник горячих клавиш по <leader> (на русском)
    ├── trouble.lua       — панель ошибок/символов
    ├── leap.lua          — быстрый переход к месту на экране (motion)
    └── toggleterm.lua    — терминал внутри Neovim
```

Подключение каталогов: главный каталог — `~/.config/nv_html`; каталог `~/.config/nvim`
— симлинк на него, поэтому обычный запуск `nvim` использует именно эту конфигурацию.

## Синхронизация с сервером (sshfs)

Проект живёт на сервере, локально монтируется его файловая система:

1. Опишите проекты в `lua/core/sshfs.lua`:
   ```lua
   local projects = {
       ["baza23"] = "baza23.ru:/home/bitrix/путь/к/проекту",
   }
   ```
2. `:SshfsMount baza23` — монтирует серверный каталог в `~/Projects/baza23`.
3. Открывайте файлы из `~/Projects/baza23` — редактирование сразу попадает на сервер.
4. `:SshfsUnmount baza23` — отмонтировать; `:SshfsList` — статус всех проектов.

**Комфорт в большом Битрикс-проекте.** sshfs ничего не скачивает заранее — файл
подтягивается при открытии и уходит на сервер при сохранении. Но Telescope и
intelephense обходят дерево сами, поэтому мусор стоит исключить из «взгляда»
Neovim. Достаточно создать в корне **монтированного проекта** файл `.ignore`
(его понимают и ripgrep для live-grep, и fd для поиска файлов):

```gitignore
upload/
bitrix/cache/
bitrix/managed_cache/
bitrix/stack_cache/
bitrix/html_pages/
bitrix/backup/
bitrix/tmp/
```

Такой же список уже зашит в настройки neo-tree и intelephense
(см. `lua/plugins/neo-tree.lua` и `lua/plugins/lsp.lua`).

Требования: macFUSE + `brew install gromgit/fuse/sshfs-mac`; ssh-ключ на сервере.

## Способ 2: git на сервере + локальный web-стек (для серьёзной разработки)

Альтернатива sshfs, когда PHP-разработки много и надо тестировать локально:
на сервере создаётся git-репозиторий, локально — копия сайта + локальный
apache/nginx + MySQL (предпочтительно с дампом продакшен-БД). Деплой:
git push → git pull на сервере (+ сброс кеша Битрикса).

Критичный момент такого подхода — **как переезжают изменения БД** (в Битриксе
инфоблоки живут в БД, а не в файлах). Деление одно и то же всегда:

| Категория | Как переносится |
|---|---|
| Файлы: шаблоны, php, js, css, `local/` | git push → git pull на сервере |
| Структура инфоблоков (типы, свойства, права), highload-блоки, почтовые шаблоны, агенты, настройки модулей | **Миграции** — это тоже код, едут в git |
| Контент инфоблоков (элементы, картинки) | Правится в админке прода; либо штатный экспорт/импорт CSV/XML, либо дамп таблиц `b_iblock*` |

Стандарт отрасли — модуль **[sprint.migration](https://github.com/andreyryabin/sprint.migration)**
(есть в маркетплейсе 1С-Битрикс): изменения БД фиксируются в файлах миграций
рядом с кодом, после деплоя на сервере выполняется
`php bitrix/modules/sprint.migration/tools/migrate.php up` — БД доводится до
актуального состояния. Модуль умеет экспортировать текущее состояние инфоблоков
в миграцию из админки. Альтернативы: более новый
[item.migrations](https://marketplace.1c-bitrix.ru/solutions/item.migrations/)
(сам сравнивает расхождения БД), свои PHP-скрипты на API Битрикса.

Для правок вёрстки/шаблонов/фронтенда sshfs-способ остаётся основным: изменения
незамедлительно видны на сервере, инфраструктура локального стека не нужна.

## Доступ к MySQL (vim-dadbod — [tpope/vim-dadbod](https://github.com/tpope/vim-dadbod), [vim-dadbod-ui](https://github.com/kristijanhusak/vim-dadbod-ui))

1. `:SshTunnel 3306` — открывает туннель localhost:3306 → бд сервера.
2. `<leader>db` (или `:DBUI`) — открывает обзорщик базы:
   - Add connection → `mysql://логин:пароль@127.0.0.1:3306/имя_базы`
   - В дереве: таблицы → `<CR>` — показать содержимое, `S` — схема.
3. В SQL-файлах: запрос под курсором или в визуальном режиме — `<CR>` (или `<Leader>S`),
   выполняется через туннель. История запросов сохраняется.

Требования: `brew install mysql-client` (клиент `mysql` должен быть в PATH;
строка `export PATH=/opt/homebrew/opt/mysql-client/bin:$PATH` в `~/.zshrc`).

## Локальная история версий (persistent undo)

Каждое изменение буфера автоматически записывается — история сохраняется на диске
(`~/.local/share/nvim/undo`) и переживает закрытие Neovim и перезагрузку:

- `<leader>fu` — telescope-undo: список всех состояний файла с диффом; `<CR>` — откат.
- `:undolist` — встроенный список; `u`/`<C-r>` — обычные undo/redo работают как всегда.

> Локальная git-история проекта (не Neovim) остаётся на усмотрение вас: fugitive ниже
> закрывает GIT для своих серверов и GitHub, а «раннее состояние после перезагрузки»
> даёт именно persistent undo.

## Git: свои серверы и GitHub (fugitive + flog + gitsigns)

Для fugitive свой git-сервер и GitHub выглядят одинаково — всё определяется remote в
`.git/config` проекта:

- `<leader>gs` — статус (стейджинг/коммит, `:Git`), стейдж файлов — `-`, коммит — `cc`
- `<leader>gc` — коммит; `<leader>gp` — push; `<leader>gP` — pull
- `<leader>gb` — blame текущего файла; `<leader>gl` — граф истории (flog)
- gitsigns рисует изменённые строки слева; `[c` / `]c` — прыжок к правке,
  `<leader>hp` — превью диффа, `<leader>hs` / `<leader>hr` — стейдж/откат правки

# Плагины: что стоит и как пользоваться

## Менеджер плагинов и стартовые экраны

### lazy.nvim — [folke/lazy.nvim](https://github.com/folke/lazy.nvim) (менеджер плагинов)
Устанавливает/обновляет плагины, управляет ленивой загрузкой.
- `:Lazy` — панель управления: статус, обновление, очистка
- `:Lazy sync` — синхронизировать (установить недостающее/удалить лишнее)
- `:Lazy update` — обновить все плагины; `:Lazy restore` — откатить к версии из lockfile
- Версии плагинов зафиксированы в `lazy-lock.json` — конфигурация воспроизводима.

### dashboard-nvim — [nvimdev/dashboard-nvim](https://github.com/nvimdev/dashboard-nvim) (стартовый экран)
Показывается при запуске Neovim без аргументов.
- `u` — обновить плагины (`Lazy update`)
- `f` — открыть файл через Telescope
- `e` — открыть дерево файлов

## Навигация и поиск

### telescope.nvim — [nvim-telescope/telescope.nvim](https://github.com/nvim-telescope/telescope.nvim) (нечёткий поиск)
Главный инструмент навигации по проекту (в т.ч. по sshfs-монтированному):
- `<leader>ff` — найти файл по имени
- `<leader>fw` — найти текст по всему проекту (live grep)
- `<leader>fb` — открытые буферы
- `<leader>fh` — поиск по документации (vim-справка)
- Примеры внутри Telescope: `Ctrl+j/k` — перемещение, `<CR>` — открыть, `Tab` — не закрывая список.

### telescope-undo.nvim — [debugloop/telescope-undo.nvim](https://github.com/debugloop/telescope-undo.nvim) (история правок файла)
- `<leader>fu` — открыть историю; поиск; `<CR>` — откат к состоянию; в превью видно дифф.

### leap.nvim — [ggandor/leap.nvim](https://github.com/ggandor/leap.nvim) (motion — быстрые прыжки)
Быстрое перемещение по видимому тексту без колеса мыши:
- `s` — прыжок к любому слову/месту на экране: набираете `s`, затем 1–2 буквы начала цели
- `S` — то же, но во всех открытых окнах (сравнение двух файлов)
- `gs` — прыжок к видимой точке в любом окне: файл открывается прямо там
- После прыжка доступны обычные операции: `d` (удалить до цели), `c` (изменить), `y` (копировать) и т.д.

### neo-tree.nvim — [nvim-neo-tree/neo-tree.nvim](https://github.com/nvim-neo-tree/neo-tree.nvim) (дерево файлов)
- `<leader>e` — открыть/закрыть боковую панель с файлами
- В дереве: `<CR>` — открыть файл, `a` — создать (имя с `/` создаст папку), `d` — удалить,
  `r` — переименовать, `c`/`x`/`p` — копировать/вырезать/вставить, `.` — показать контекстное меню.
- В Битрикс-проектах скрывает `upload/` и кеш (`bitrix/cache` и т.п.); `.htaccess` и другие
  dot-файлы видны. Для Telescope — файл `.ignore` в корне проекта (см. раздел sshfs).

### nvim-treesitter — [nvim-treesitter/nvim-treesitter](https://github.com/nvim-treesitter/nvim-treesitter) (подсветка и парсеры)
Основа для дерева разбора HTML/PHP/CSS/JS/SQL: на нём работают подсветка синтаксиса,
vim-matchup, nvim-ts-autotag и отступы. Грамматики ставятся автоматически при первом
запуске (`:TSUpdate` при обновлении).

### vim-matchup — [andymass/vim-matchup](https://github.com/andymass/vim-matchup) (парные теги и скобки)
Подсветка и прыжки по парным элементам (Treesitter; html, php+html, xml и др.):
- стоит курсором на имени тега — парный тег (открывающий ↔ закрывающий) подсвечивается
- `%` — прыжок к парному тегу/скобке и обратно
- `ds%`, `cs%`, `ys%` — операции изменения (изменить, окружить) по паре

### rainbow-delimiters.nvim — [hiphish/rainbow-delimiters.nvim](https://github.com/hiphish/rainbow-delimiters.nvim) (радужные вложенные пары)
Уровни вложенности раскрашиваются разными цветами: открывающий и закрывающий
тег одного элемента — одного цвета, их родителей — другого. Наглядно в сложной
верстке. Цвета нейтральные (отдельной интеграции с kanagawa у плагина нет).

## LSP и автодополнение

### mason.nvim — [mason-org/mason.nvim](https://github.com/mason-org/mason.nvim) + [mason-lspconfig](https://github.com/mason-org/mason-lspconfig.nvim) (установка LSP-серверов)
Установлен набор под ваш стек: `html`, `cssls` (css/scss), `ts_ls` (js/ts),
`intelephense` (PHP/Битрикс), `sqlls` (SQL), `emmet_ls` (HTML-эммет), `lua_ls` (конфиг самого nvim).
- `:Mason` — менеджер пакетов (поставить/обновить/удалить инструмент)
- `:LspInfo` — какой сервер работает в текущем буфере
- intelephense не индексирует мусор Битрикс-проекта (upload, кеш, бэкапы —
  список исключений в `lua/plugins/lsp.lua`)

### LSP — [neovim/nvim-lspconfig](https://github.com/neovim/nvim-lspconfig) (в буферах с кодом)
- `gd` — перейти к определению; `gi` — к реализации; `<Leader>D` — к типу
- в html-файлах `gd` работает иначе: открывает выбор определений класса/ID
  в файлах стилей (см. `lua/core/cssjump.lua` и таблицу клавиш «LSP и код»)
- `K` — документация под курсором (hover)
- `<Leader>lr` — переименовать символ (во всём проекте)
- `<Leader>la` — быстрые действия (код-акции)
- `<Leader>lf` — форматировать файл средствами LSP
- `<Leader>ls` — подсказка по сигнатуре функции при вводе аргументов
- Ошибки отображаются в тексте (`■`) и в колонке слева.

### nvim-cmp — [hrsh7th/nvim-cmp](https://github.com/hrsh7th/nvim-cmp) (автодополнение)
Источники: LSP, файлы (path), буфера, SQL-колонки (dadbod), сниппеты (native Neovim).
- `<C-Space>` — вызвать автодополнение вручную
- `<Tab>`/`<S-Tab>` — выбрать следующий/предыдущий вариант
- `<CR>` — принять предложение; `<C-e>` — закрыть меню
- В командной строке `:` и `/` тоже работает автодополнение.
- Сниппеты: `<Tab>` внутри сниппета — прыжок к следующему плейсхолдеру.

### nvim-ts-autotag — [windwp/nvim-ts-autotag](https://github.com/windwp/nvim-ts-autotag) (авто-пары html-тегов)
Управляет парой тегов по дереву Treesitter (html, xml, php+html и др.):
- при вводе `<div>` закрывающий `</div>` дописывается автоматически
- правка имени одного тега меняет и парный ему: `<div></div>` →
  `cwspan<Esc>` даёт `<span></span>` — работает на любом из двух тегов,
  в том числе внутри смешанного php+html
- если автозакрытие не нужно, его можно отключить в `lua/plugins/autotag.lua` (`enable_close = false`)

### conform.nvim — [stevearc/conform.nvim](https://github.com/stevearc/conform.nvim) (форматирование при сохранении)
На сохранении автоматически форматирует: prettier (html/css/scss/js/ts/json),
sql-formatter (SQL), stylua (lua).
- `:ConformInfo` — какие форматтеры активны в текущем файле
- Ручной запуск: `<Leader>lf` или через LSP-форматирование.

### nvim-lint — [mfussenegger/nvim-lint](https://github.com/mfussenegger/nvim-lint) (линтеры)
Eslint для js/ts — выводит на экран после сохранения файла; результаты видны в панелях Troubles.

## Отображение

### bufferline.nvim — [akinsho/bufferline.nvim](https://github.com/akinsho/bufferline.nvim) и lualine — [nvim-lualine/lualine.nvim](https://github.com/nvim-lualine/lualine.nvim) (статусная строка)
Вкладки вверху с иконками файлов и счётчиками ошибок; снизу — режим, git-ветка,
ошибки/предупреждения в статусной строке, кодировка. Цвета обеих — из темы kanagawa.
- `<Tab>` — следующая вкладка; `<S-Tab>` — предыдущая
- `<Leader>x` — выбрать вкладку на закрытие; `<C-x>` — закрыть все, кроме текущей

### which-key.nvim — [folke/which-key.nvim](https://github.com/folke/which-key.nvim) (подсказки команд на ходу)
Справочник горячих клавиш прямо Neovim: нажали `<leader>` и держите — на экране все
доступные команды с описаниями (все подписи на русском, сгруппированы логически:
Поиск, Git, База данных, LSP, Панели, Вид интерфейса).
- `<leader>?` — все клавиши текущего буфера
- Подсказка появляется автоматически при начале комбинации и прерывается, если вы нажали уже известную клавишу.

### trouble.nvim — [folke/trouble.nvim](https://github.com/folke/trouble.nvim) (панели: ошибки, символы)
- `<leader>qq` — все ошибки/предупреждения по проекту
- `<leader>qQ` — ошибки текущего файла
- `<leader>qf` — список quickfix; `<leader>qL` — локальный список
- `<leader>cs` — символы файла (дерево функций/переменных)
- `<leader>cl` — ссылки/определения текущего символа

### kanagawa — [rebelot/kanagawa.nvim](https://github.com/rebelot/kanagawa.nvim) (цветовая тема, вариант wave)
Тёплая тёмная палитра: тёмно-бежевый фон, янтарные/оливковые/розовые акценты,
умеренный контраст (спокойная для глаз, без холодной синевы). Непрозрачный фон.
Вариант переключается в `lua/plugins/kanagawa.lua`:
- `wave` — основная тёплая тёмная
- `dragon` — темнее и спокойнее (минимум акцентов)
- `lotus` — светлая тёплая
- `:colorscheme kanagawa-dragon` / `:colorscheme kanagawa-lotus` — на лету

### nvim-autopairs — [windwp/nvim-autopairs](https://github.com/windwp/nvim-autopairs) (авто-закрытие скобок и кавычек)
При наборе `(` автоматически добавляется `)`; кавычки `'`/`"` тоже.
- Интегрировано с автодополнением: выбор функции из подсказок получает скобки автоматически (`sort` → `sort(`)
- `<C-v>` перед вставкой из буфера отключает автозакрытие (вставка «как есть»)

### indent-blankline.nvim — [lukas-reineke/indent-blankline.nvim](https://github.com/lukas-reineke/indent-blankline.nvim) (линии отступов)
Тонкие вертикальные линии по уровням отступов — сразу видно вложенность блоков:
где начинается/заканчивается функция, блок if, разметка HTML.

# Установка на чистый Mac

Neovim 0.9.5+ минимум (актуальный конфиг рассчитан на 0.12+ — treesitter main-branch).

```bash
# 0. Компилятор (нужен для сборки tree-sitter грамматик)
xcode-select --install

# 1. Основное
brew install neovim node ripgrep tree-sitter-cli

# 2. MySQL-клиент (для vim-dadbod)
brew install mysql-client
#   затем в ~/.zshrc добавьте строку:
#   export PATH=/opt/homebrew/opt/mysql-client/bin:$PATH

# 3. sshfs (если проекты идут через SSH-монтаж)
brew install --cask macfuse            # macFUSE — до sshfs!
brew install gromgit/fuse/sshfs-mac
#   после установки macFUSE: расширенные настройки системы → разрешить
#   системное расширение и перезагрузить Mac

# 4. Сам конфиг (вместо <ваш-репозиторий> — адрес вашего git/GitHub)
git clone <ваш-репозиторий> ~/.config/nv_html
ln -sfn ~/.config/nv_html ~/.config/nvim
nvim                                    # первый запуск доставит плагины и LSP сам
```

# Установка на Linux

Требования те же по смыслу: Neovim 0.12+, node.js (для npm-пак Mason: LSP-серверы),
ripgrep (поиск Telescope), tree-sitter-cli и компилятор C (сборка грамматик),
mysql-клиент, sshfs + fuse3.

Пакет `neovim` в репозиториях дистрибутивов обычно старее 0.11, поэтому Neovim
рекомендуется ставить из офиц. релизов (tarball или AppImage, без компиляции):

```bash
# Neovim 0.12+ из офиц. релиза (x86_64; для arm64 файл nvim-linux-arm64.tar.gz)
curl -LO https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.tar.gz
sudo rm -rf /opt/nvim && sudo tar -C /opt -xzf nvim-linux-x86_64.tar.gz
sudo ln -sf /opt/nvim-linux-x86_64/bin/nvim /usr/local/bin/nvim
```

Затем системные зависимости (в зависимости от дистрибутива):

```bash
# Ubuntu / Debian
sudo apt install git build-essential curl ripgrep fd-find nodejs npm sshfs fuse3 default-mysql-client
#   на Debian/Ubuntu бинарник называется fdfind — Telescope ищет 'fd':
sudo ln -sf $(which fdfind) /usr/local/bin/fd
npm install -g tree-sitter-cli

# Fedora
sudo dnf install git gcc make curl ripgrep fd-find nodejs npm sshfs fuse3 mysql
npm install -g tree-sitter-cli

# Arch
sudo pacman -S --needed git base-devel ripgrep fd nodejs npm sshfs fuse3 mariadb-clients
npm install -g tree-sitter-cli
```

Настройка самой конфигурации после системных пакетов (одинакова для всех платформ):

```bash
git clone <ваш-репозиторий> ~/.config/nv_html
ln -sfn ~/.config/nv_html ~/.config/nvim
nvim
```

Для доступа к БД MySQL по SSH-туннелю `default-mysql-client` / `mysql` должны
находиться в PATH (в стандартных путях дистрибутивов — уже находятся).

# Первый запуск и проверка (любая платформа)

1. `nvim` — first run: lazy.nvim скопирован сам, затем автоматически
   `Lazy sync` (все плагины), mason поставит LSP-серверы (нужен node),
   treesitter соберёт грамматики (нужен tree-sitter-cli и компилятор).
   На медленной сети подождите окончание всех загрузок внизу окна.
2. Проверки:
   - `:checkhealth` — общая диагностика (ищите строки ERROR/WARN)
   - `:Mason` — все LSP-серверы установлены (html, cssls, ts_ls, intelephense, sqlls, emmet_ls, lua_ls)
   - `:LspInfo` — в открытом html/php-файле виден работающий сервер
   - `:InspectTree` — в html-файле открывается дерево разбора (значит грамматики есть)
3. Настройте свои проекты в `lua/core/sshfs.lua` (таблица `projects`),
   подключение к БД — после `:SshTunnel 3306` в DBUI (см. разделы выше).
4. Версии плагинов закреплены в `lazy-lock.json` — обновление: `:Lazy update`,
   откат к проверенной точке: `:Lazy restore`.
