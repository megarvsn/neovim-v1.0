# Глава 9. Локальная история версий: persistent undo

Цель: восстановить файл из любой точки его истории — даже после перезагрузки Mac.
Время: ~5 минут. Каждый буфер ведёт свою историю на диске
(`~/.local/share/nvim/undo`), git для этого не нужен.

## Обычный undo/redo

- `u` — откат пошагово; `Ctrl+r` — redo.
- Undo-дерево ветвится: если после отката вы начинаете другую правку, старую
  ветку это не затирает (переключение: `g-` / `g+` — назад/вперёд по веткам).

## `<leader>fu`: вся история файла в Telescope

Список **всех** состояний файла (подобно git log, но локально и по каждой отдельной правке):

- поиск по тексту, `Ctrl+j/k` — движение;
- в превью справа — дифф состояния относительно актуального вида файла;
- `<CR>` — откат файла к этому состоянию.

Практика: сделайте несколько разных правок в файле (строки, классы, пустые
строки), затем `<leader>fu` — посмотрите на диффы в превью и откатитесь на
3–4 шага назад. `Ctrl+r` при желании вернёт обратно (откат — тоже правка).

## Откат во времени (без Telescope)

- `:earlier 5m` / `:later 5m` — на 5 минут назад/вперёд;
- `:earlier 10` / `:later 10` — на 10 правок назад/вперёд;
- `:undolist` — список веток undo.

## Что переживает, а что нет

| Событие | История |
|---|---|
| Закрытие Neovim | сохраняется (persistent undo) |
| Перезагрузка Mac | сохраняется |
| Прыжок по веткам undo | `g-`/`g+`, или через `<leader>fu` |
| git-история проекта | отдельная (fugitive, глава 6) — это про коммиты, а не про наборы правок |

Разделение такое: persistent undo — «откатить мои правки»
(откат без коммитов и без git);
git — «вернуть состояние версии проекта». Полезны оба, путать не надо.
