# Глава 7. Git-цикл

Цель: править, стейджить и коммитить, не выходя из редактора — и на своих
серверах, и на GitHub.
Время: ~15 минут. Работайте в проекте под git.

## Знаки правок (gitsigns)

Слева от строк — знаки: изменённая строка, добавленная (+), удалённая (полоса).
- `]c` / `[c` — следующая / предыдущая правка в файле
- `<leader>hp` — превью диффа правки (что поменялось, по сравнению с git)
- `<leader>hs` — стейджировать правку; `<leader>hr` — откатить правку

Практика: измените строку, `<leader>hp` — увидите diff, `<leader>hr` — правки
как не бывало, `<leader>hs` — зафиксирована в стейджинге.

## Статус и коммит (fugitive)

- `<leader>gs` — git-статус. В нём:
  - `-` на строке файла — стейдж/анстейдж (переключатель)
  - `cc` — коммит (в буфере сообщения; сохранение — коммит)
  - `:Git log` / `:Git diff` — история и диффы
- `<leader>gc` — начать коммит; `<leader>gp` — push; `<leader>gP` — pull.

## Кто менял строку: blame (`<leader>gb`)

Git blame по текущему файлу показывает у каждой строки автора и коммит — ответ на
вопрос «а кто это писал». Постоянный показ в строках: `:Gitsigns toggle_current_line_blame`.

## Граф истории: `<leader>gl`

Flog показывает дерево коммитов с авторами. В нём `:Git checkout <sha>` — вернуться
к коммиту.

## Полный цикл (сделайте сейчас)

1. Внесите правки в файл — смотрите знаки у строк слева.
2. `]c` — пройдитесь по правкам, `<leader>hs` — добавьте нужные в стейдж.
3. `<leader>gs` — общий статус; `cc` — коммит; сообщение; `:wq`.
4. `<leader>gl` — ваш коммит в граф; `<leader>gp` — push.

## Если нужно откатить

- Непомещённое в коммит: `u` (undo) или откат отдельной строки — `<leader>hr`.
- Файл целиком к последнему коммиту: `:Git checkout %` (текущий буфер).
- Отложить изменения: `:Git stash`, вернуть — `:Git stash pop`.

> Свои git-серверы и GitHub работают одинаково — всё решает remote в `.git/config`.
