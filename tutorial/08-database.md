# Глава 8. База данных: туннель, обзорщик, запросы

Цель: посмотреть таблицу серверной БД и выполнить запрос, не выходя из Neovim.
Время: ~10 минут. Полная справка: [docs/database.md](../docs/database.md).

## 1. Туннель

Вся работа с БД идёт через SSH-туннель — первым делом откройте его:

```
:SshTunnel 3306
```

localhost:3306 теперь смотрит на MySQL на сервере (туннель открывается в
плавающем терминале; закрывается штатно `<C-\>`).

## 2. Обзорщик базы: `<leader>db` (или `:DBUI`)

- Первый раз: `Add connection` → строка
  `mysql://логин:пароль@127.0.0.1:3306/имя_базы` (параметры вашего сервера).
- Далее само запомнит (`~/.local/share/nvim/db_ui/connections.json`).
- В дереве: схема → таблица. `<CR>` на таблице — содержимое, `S` — схема
  (колонки, типы). Запрос и результат — в паре буферов ниже.

## 3. Выполнение запроса из SQL-файла

В любом SQL-файле (или буфере результата):

- Запрос под курсором (или выделенный визуально) → `<CR>` — выполнить через
  туннель; тот же эффект `<Leader>S`.
- `<Leader>W` — сохранить текущий SQL (история запросов dadbod).

Практика: создайте `query.sql`, напишите

```sql
SELECT first_name, last_name FROM b_user ORDER BY id DESC LIMIT 5;
```

Курсор внутри запроса → `<CR>`. Результат — в соседнем буфере.

## Дополнительно

- `:DB mysql://логин@127.0.0.1:3306/имя` — привязать текущий SQL-буфер к
  подключению (без DBUI).
- `:DBUILastQueryInfo` — показать последний выполненный запрос и его результат.

## Чего не делать

- Изменяющие запросы (UPDATE/DELETE) без WHERE — dadbod честно выполнит их на
  **боевой** базе. Проверяйте WHERE и сначала `SELECT`.
- Контент инфоблоков из БД обычно не правят напрямую — только по осознанному
  решению (см. «Как переезжают изменения БД» в [docs/sshfs.md](../docs/sshfs.md)).
