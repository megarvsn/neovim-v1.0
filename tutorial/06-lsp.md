# Глава 6. Работа с кодом: LSP

Цель: использовать подсказки, ошибки и переименование как в «большой» IDE.
Время: ~15 минут. Откройте php- или js-файл проекта (в html — вёрстка, там LSP меньше).

## Автодополнение

- Печатаете — меню всплывает само. `<C-Space>` — вызвать вручную.
- `<Tab>` / `<S-Tab>` — выбрать следующий/предыдущий вариант; `<CR>` — принять;
  `<C-e>` — закрыть меню.
- Источники: LSP (функции/переменные, в т.ч. сниппеты от сервера), пути,
  содержимое буферов, SQL-колонки (в SQL-файлах и DBUI).
  В командной строке `:` и `/` — тоже.
- Интеграция с автопарами: выбираете функцию из списка — скобки дописываются
  сами (`sort` → `sort(`).

## Ошибки и предупреждения

- Проблемные места подчёркиваются в тексте, счётчик — в статусной строке.
- `<leader>qq` — панель всех ошибок проекта (Trouble); `<leader>qQ` — текущего файла.
- В панели: `<CR>` — прыжок к проблеме, `q` — закрыть панель
  (`<Esc>` — закрыть preview и вернуться в файл, панель остаётся).

Проверить любой сервер: `:LspInfo` (какой LSP работает в текущем буфере и его статус).

## Документация и переходы

| Клавиши | Действие |
|---|---|
| `K` | документация по символу под курсором (hover-окно) |
| `gd` | перейти к определению (php-функция, js-переменная) |
| `<leader>lC` | список определений класса/ID в стилях — работает из любого файла проекта (php+html или css) |
| `<leader>cl` | все места символа по проекту — определения и ссылки (панель Trouble) |
| `gi` | перейти к реализации |
| `<Leader>D` | перейти к типу |
| `Ctrl+o` | вернуться обратно (после любого `gd`) |
| `<Leader>ls` | подсказка по сигнатуре при наборе аргументов |
| `]d` / `[d` | следующая / предыдущая ошибка (её текст всплывает у курсора) |

В html-файлах `gd` «отдан» поиску определений class/ID в стилях (см. главу 5).

## Переименование символа (по всему проекту)

1. Курсор на имени функции/переменной → `<Leader>lr` → наберите новое имя → `<CR>`.
2. Сервер переименовывает во всех файлах, где символ используется, — правки
   применяются сразу; полный перечень изменённого покажет git (`<leader>gs`).

## Быстрые действия (code actions)

- `<Leader>la` — контекстные исправления сервера (extract method, добавить
  имплементацию и т.п.); для выбора — стандартное меню vim.ui.select.

## Переформатировать (если не сработало сохранение)

- `<Leader>lf` — форматировать файл средствами LSP.

## Практика

1. Откройте PHP-файл, встаньте на вызов функции → `K` (документация) → `Esc`.
2. `gd` — к определению; `Ctrl+o` — назад.
3. Переименуйте переменную через `<Leader>lr` — посмотрите в git (`<leader>gs`),
   что изменилось. Чтобы безболезненно откатить такие массовые изменения,
   сперва сделайте коммит (глава 7).
