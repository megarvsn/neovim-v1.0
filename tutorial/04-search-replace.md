# Глава 4. Поиск и замена: буфер, файл, проект

Цель: менять текст в открытом файле и во всём проекте — всё сразу или
с подтверждением каждого вхождения. Время: ~20–25 минут.
Откройте html-файл с вёрсткой.

## Поиск в буфере (открытом файле)

- `/текст` — поиск вперёд; `?текст` — назад; `n`/`N` — следующее/предыдущее
  совпадение; `<Esc>` — снять подсветку.
- `*` / `#` — искать слово под курсором вниз/вверх (без набора текста).
- `/` с пустым шаблоном повторяет последний поиск: `/` + Enter.
- Результаты поисковой навигации не собираются в список — список даёт поиск
  по проекту (ниже) или Telescope (`<leader>f/` — нечёткий поиск по файлу, глава 2).

## Замена в буфере: `:s`

Формула: `:[диапазон]s/что/чем/флаги`.

| Команда | Что делает |
|---|---|
| `:s/old/new/` | первое вхождение в текущей строке |
| `:s/old/new/g` | все вхождения в текущей строке (`g` — global) |
| `:%s/old/new/g` | **сразу все во всём файле** (`%` — весь файл; без вопросов) |
| `:%s/old/new/gc` | **с подтверждением каждого вхождения** (`c` — confirm) |
| `:'a,'bs/old/new/g` | в диапазоне между метками a и b |
| `V`, потом `:s/old/new/g` | в визуальном выделении (`'<,'>` подставится само) |

- Ответы в подтверждении (`gc`): `y` — заменить, `n` — пропустить,
  `a` — заменить всё оставшееся без вопросов, `q` — выйти, `l` — заменить
  это и выйти; `Ctrl+E`/`Ctrl+Y` — прокрутить экран вокруг совпадения.
- Регистр: поиск чувствителен к регистру. Флаг `i` — без учёта регистра
  (`:%s/Class/class/gi`); внутри шаблона то же делает `\c`, а `\C` — наоборот,
  всегда с учётом регистра.
- `:%s//new/g` — «что» пустое: используется последний поиск (набрали `/`, потом заменили).
- `.` повторяет последнюю замену `:s`. `&` — то же в текущей строке.

## Поиск и замена по проекту средствами Neovim: quickfix

Схема «собрал совпадения → прошёлся заменой по всем файлам»:

```vim
:vimgrep /btn-primary/ **/*.html    " найти всё по проекту → в quickfix-список
:copen                              " открыть список (ходить: ]q / [q, глава 2)
:cfdo %s/btn-primary/btn-secondary/gc   " заменить в каждом найденном файле
:cfdo update                        " записать на диск только изменённые файлы
```

- `:cfdo` — команда к **каждому файлу** из списка; `:cdo` — к **каждой строке**
  списка. Для `%s`-замены нужен `:cfdo`: `:cdo %s/…` заменяет лишь первое
  вхождение в каждой найденной строке.
- Два режима: `:cfdo %s/old/new/g` — сразу все вхождения во всех файлах;
  `:cfdo %s/old/new/gc` — подтвердить каждое.
- По открытым буферам (вкладкам): `:bufdo %s/old/new/g`.
- Результаты Telescope (`<leader>fw`) тоже попадают в quickfix — можно искать
  глазами и делать `:cfdo` без `:vimgrep`.
- Перед массовой заменой — коммит (`<leader>gc`, глава 7): откат через git
  надёжнее, чем undo по отдельным файлам.

## Замена по проекту: Spectre (`<leader>fs`)

С превью каждой замены до её применения (плагин nvim-spectre):

1. `<leader>fs` — открыть панель (в visual-режиме — текст будет подставлен
   в поиск). Для замены в текущем файле: `<leader>fS`.
2. Вверху два поля — поиск / замена. Поиск идёт по проекту вживую.
   `<Tab>`/`<S-Tab>` — перескок между полями; `ti` — не учитывать регистр.
3. **Сразу все вхождения**: `<leader>R` (replace all).
4. **Выборочно**: `dd` — исключить/вернуть строку из замены;
   `<leader>rc` — заменить только текущую строку; `<leader>R` — применить
   все отмеченные.
5. `<leader>q` — отправить список результатов в quickfix (дальше можно
   `:copen` и `:cfdo`).

Шаблоны поиска здесь — синтаксис ripgrep (см. справочник ниже и
[docs/regex.md](../docs/regex.md)).

## Подглава: регулярные выражения

Шаблоны Neovim («vim-regex») работают в `/`, `:s`, `:g` и `:vimgrep`.
Полный справочник синтаксиса и подробные примеры — отдельным файлом:
[docs/regex.md](../docs/regex.md). Ядро, без которого обходиться нельзя:

### Режим «магии»

По умолчанию (magic): спецсимволы — `.` `*` `[` `~` и после `\` — многие
(`\(`, `\+`, `\|`…). Для сложных шаблонов удобнее режим very magic — `\v`:
**все** спецсимволы пишутся без бэкслеша, как в «обычных» регулярках:

```vim
/\d\+                   " цифры подряд в magic — бэкслеши почти везде
/\v\d+                  " то же самое в very magic
/\v(\d{2}):(\d{2})      " два числа по 2 цифры через двоеточие, группы 1 и 2
```

В `\v` всё наоборот и для обычных символов: `(` — группа, а `\(` —
литеральная скобка; литеральный `$` — `\$`, литеральный `<` — `\<` (но
`<` без бэкслеша — граница слова).

### Ядро синтаксиса

| Символ | Смысл |
|---|---|
| `.` | любой символ |
| `^` / `$` | начало / конец строки |
| `*` | предыдущий элемент — 0 и более раз |
| `\+` / `+` (в `\v`) | 1 и более раз |
| `\?` / `?` (в `\v`) | 0 или 1 раз |
| `\{n,m}` / `{n,m}` (в `\v`) | от n до m раз |
| `\{-}`, `\{-n,m}` | лениво — как можно меньше (ленивый «1 и более»: `\{-1,}`) |
| `\(…\)` / `(…)` (в `\v`) | группа (в шаблоне — `\1`, в замене — `\1`…`\9`) |
| `[abc]`, `[^abc]` | класс: любой из перечисленных / любой кроме |
| `[[:digit:]]` | POSIX-класс (внутри `[ ]` shorthand `\d` не работает) |
| `\d \w \s` | цифра / буква-цифра-подчёрк / пробел или таб (`\D \W \S` — инверсии) |
| `\<` / `\>` | начало / конец слова |
| `\zs` / `\ze` | от чего начинается / чем заканчивается совпадение |
| `\|` / `|` (в `\v`) | ИЛИ |
| `\n`, `\_s` | новая строка; любой пробельный символ, включая перенос строки |
| `\c` / `\C` | игнорировать регистр / всегда учитывать |

### Примеры

```vim
" добавить всем классам префикс wrap:  class="nav"  →  class="wrap nav"
:%s/class="\([^"]*\)"/class="wrap \1"/g

" 27.10.2026 → 2026-10-27 (группы \1…\3)
:%s/\v(\d{2})\.(\d{2})\.(\d{4})/\3-\2-\1/g

" заменить только слово целиком (btn-primary не пострадает)
:%s/\<btn\>/button/g

" убрать все html-теги в файле
:%s/<[^>]*>//g
```

## Практика (сделайте сейчас)

1. `*` на классе в файле, `n`/`N`. `:%s/btn/btn-lg/gc` — пройдите
   каждое вхождение (`a` на середине — согласиться на всё остальное).
2. `:vimgrep /nav-item/ **/*.html`, `:copen`, `]q` — осмотрите список;
   `:cfdo %s/nav-item/nav-link/gc`, затем `:cfdo update`.
3. `<leader>fs`: замените `nav-link` → `nav-item` обратно; `dd` исключите
   один файл, `<leader>rc` — замените только одну строку, `<leader>R` — остальные.
4. Откройте [docs/regex.md](../docs/regex.md) и попробуйте 2–3 рецепта
   из раздела «Рецепты» на копии файла.
